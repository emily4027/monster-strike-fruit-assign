# 🍏 怪物彈珠 - 果實分配助手 (Monster Strike Fruit Allocator)

為《怪物彈珠》玩家設計的網頁工具，解決「果實分配複雜、庫存難以計算」的問題。
管理角色的果實需求、盤點庫存，並透過雲端同步在不同裝置存取資料。

🔗 **線上使用**：https://emily4027.github.io/monster-strike-fruit-assign/


🧰 **工具箱首頁**：https://emily4027.github.io/monster-strike-toolbox/

---

## ✨ 功能

### ☁️ 雲端同步與多重存檔
- **Google 登入 (Firebase Authentication)**：可在本頁頁首按「🔑 Google 登入」，或在[工具箱首頁](https://emily4027.github.io/monster-strike-toolbox/)登入（兩邊共用登入狀態）；登入後頁首顯示頭像、名稱與登出鈕。
- **登出**：登出前會先送出尚未儲存的變更；登出後畫面會換回這台電腦的本機（離線）資料，雲端資料不會留在畫面與瀏覽器快取中。
- **自動儲存**：編輯後約 1 秒自動寫入 Firestore，頁首狀態燈號會顯示「雲端 / 儲存中 / 離線」。
- **多重存檔**：預設 4 個存檔，可 ➕ 新增、🗑️ 刪除（預設存檔不可刪）、✏️ 重新命名；選單優先顯示存檔名稱，頁面標題顯示為「○○的果實分配」。
- **存檔清單跨裝置同步**：登入後，存檔清單與名稱存在雲端，所有裝置看到同一份清單。第一次登入時會上傳這台電腦的清單與資料；之後以雲端清單為準。若這台電腦有「雲端清單沒有、但本機有資料」的存檔，登入時會詢問是否加入雲端（按取消的話下次登入會再問）。登出後會換回這台電腦自己的存檔清單。
- **刪除存檔**：登入時會確認兩次，第二次確認後才會連同雲端資料一起刪除，所有裝置都會看不到；任何一次按取消都不會刪除。未登入時只刪除這台電腦上的存檔。
- **多台裝置同時開著**：存檔前會先確認雲端沒有被其他裝置改過，不會直接蓋掉另一台的修改。存檔資料被其他裝置改過時，會先把這台剛才的版本下載成 JSON 備份，再載入雲端最新資料，請重新操作（需要的話可用「載入備份」找回）；存檔清單則會自動合併兩邊的新增、刪除與改名。
- **離線備援**：未登入或雲端讀取失敗時，自動使用瀏覽器 LocalStorage。
- **手動備份**：「💾 下載備份」可以只下載目前存檔，或把全部存檔下載成一個 JSON 檔。「📂 載入備份」可以選擇**另存成新存檔**或**覆蓋目前存檔**（覆蓋前會先自動下載目前資料的備份）；全部存檔的備份檔可以挑其中一個載入，或全部另存成新存檔。「🔥 全部初始化」只會重置目前選取的存檔。
- **↩️ 復原 / ↪️ 重做**：畫面左下角的按鈕（或 Ctrl+Z / Ctrl+Y、Ctrl+Shift+Z），可以復原最近 20 步修改，例如重置、刪除角色、自動加註記、抽卡匯入、果實分配。紀錄只存在目前分頁，重新整理、切換存檔、載入其他裝置的最新資料後會清空。復原後會照常存回雲端。（統一名字時改寫到抽卡統計的名稱不會跟著復原。）
- **快速開啟**：已登入的使用者會從 sessionStorage 快取立即還原畫面，不必等待雲端載入。

### 🎒 庫存管理
- **英雄 BANK**：對應遊戲內 7 個鳥籠，每個鳥籠可指定一種果實。
- **角色暫存箱**：可建立「倉庫角色」（例如 4 星角），每位有 4 個果實欄位，用來暫存多餘果實。
- **自訂果實類型**：可新增果實（歸類為「加擊類」或「其他」）或刪除果實；刪除時會一併清除各處的分配與庫存。
- **總覽儀表板**：左側「加擊類」、右側「其他類」，每種果實顯示 **分配 / 已獲得 / 庫存**，並以狀態判斷是否足夠：

  | 顯示 | 意義 |
  |------|------|------|
  | ✓ 剛好 | 庫存 = 尚未取得的需求 |
  | 📦 多 N | 庫存多出 N 顆 |
  | ⚠️ 缺 N | 還缺 N 顆 |

  > 計算方式：尚需 = 分配 − 已獲得；差額 = 庫存 − 尚需。庫存 = 英雄 BANK + 角色暫存箱。

### 👥 角色與果實分配
- **主力角色清單**：新增、搜尋、重新命名、刪除角色（更名時分配與已獲得狀態會一併轉移，並防止重複名稱）。
- **🎰 從抽卡統計匯入**：把[抽卡統計](https://emily4027.github.io/monster-strike-gacha/)紀錄裡抽到的角色直接加進來（登入時讀雲端紀錄，未登入時讀這台電腦的紀錄）。每個存檔綁定一個抽卡帳號（第一次匯入時綁定，之後要按「更換帳號」才能換；其他存檔在用的帳號會標出來並提醒），角色依月份收合（點月份展開），每隻角色可選「新增到主力 / 新增到倉庫 / 對應到已有角色 / 不需要 / 先不處理」：
  - 抽到多隻同名角色時，第二隻起自動編號為「虹夏-2」「虹夏-3」……（主力與倉庫一起算）。
  - 一開始每隻角色都是「先不處理」，旁邊顯示建議的動作（已經手動新增過的同名角色會建議「對應」）；勾選活動後按「套用建議」可一次套用。名稱不同的也可以手動選擇對應。
  - 對應到名字不同的角色（例如錯字）時，可以選擇統一用哪個名字：改果實分配的角色名稱，或改抽卡統計的紀錄（登入時才會改抽卡統計，所有帳號寫成同一個名字的紀錄會一起改）。
  - 「已匯入」分頁可取消對應（角色不會被刪除），「🗑️ 垃圾桶」分頁可找回選了「不需要」的角色。
  - 匯入後才在抽卡統計改角色名字也沒關係，會自動接回原本的匯入狀態。
- **快速輸入**：主力角色、倉庫角色、果實名稱的輸入框按 Enter 即可新增（使用注音等輸入法選字時的 Enter 不會觸發）。
- **分配表**：每位角色 4 個果實欄位，每顆果實有獨立勾選框，勾選代表「已獲得」；全部完成的角色整列以綠色標示。
- **搜尋與排序**：可搜尋角色名稱或果實，可選「僅顯示搜尋結果」「隱藏已完成分配」，並依「未完成分配數量」由少到多或由多到少、或「抽卡日期 (新到舊)」排序（依對應的抽卡活動日期，沒有對應的排最下面）；標題旁顯示待辦角色數。
- **快速分配組合**：選擇角色後一鍵套用，角色名稱會自動加上（或換成）對應的註記，例如「虹夏(同族)」。註記只在果實分配使用，和抽卡統計比對名字時會先拿掉：

  | 按鈕 | 果實 | 註記 |
  |------|------|------|
  | 同族組合 | 同族加擊、同族加命擊、同族加擊速 | (同族) |
  | 戰型組合 | 戰型加擊、戰型加命擊、戰型加擊速 | (戰型) |
  | 擊種組合 | 擊種加擊、擊種加命擊、擊種加擊速 | (擊種) |
  | 速必雙削 | 將消、兵消、速必 | (雙削) |
- **依分配自動加註記**：在分配表改果實時，如果分配了同族 / 戰型 / 擊種其中一類的 2 顆以上果實（例如同族加擊、同族加擊速、速必），或同時分配了將消與兵消，角色名稱會自動加上「(同族)」或「(雙削)」等註記。分配改掉、不再符合時（包含「🔄 重置」）會自動拿掉註記。按「🏷️ 依分配自動加註記」可一次更新現有所有角色的註記（還沒分配果實的角色不動）。同時符合兩種時不會換註記。

### ⚡ 果實轉移
從「英雄 BANK」或「倉庫角色」將果實移到：
- **主力角色**：填補尚缺的欄位，並自動標記為「已獲得」；
- **英雄 BANK**：移到空閒鳥籠；
- **倉庫角色**：移到空的果實欄位。

只需選擇目標類型與目標（角色 / 鳥籠），果實欄位會自動選擇：主力角色放進第一個分配到此果實且未獲得的欄位，倉庫角色放進第一個空欄位。

### 📥 從分配表直接搬入
分配表中「已分配、未獲得」且庫存（鳥籠或倉庫）有這顆果實的欄位，會出現 📥 按鈕；滑鼠移上去會顯示「庫存 X / 尚需 Y」，庫存不夠分時可以先決定要給誰。點擊後選擇要從哪個鳥籠或倉庫角色拿，確認後該果實會從來源移除，並把這個欄位標記為「已獲得」，不必再到鳥籠或倉庫找果實放在哪裡。

## 🚀 快速開始

### 線上使用
直接開啟：https://emily4027.github.io/monster-strike-fruit-assign/
如需雲端同步，按頁首的「🔑 Google 登入」即可。

### 本地開發
本專案為純靜態網頁，但整合了 Firebase，**請透過本機伺服器開啟**，不要直接用 `file://` 開啟 `index.html`：

```bash
git clone https://github.com/emily4027/monster-strike-fruit-assign.git
cd monster-strike-fruit-assign

# 任選一種方式啟動本機伺服器
python -m http.server 8000     # 然後開啟 http://localhost:8000
# 或使用 VS Code 的 Live Server 擴充功能
```

未登入時會以離線模式運作（資料存在瀏覽器 LocalStorage）。

## 🧩 開發筆記 (新增功能前先看)

`script.js` 依區塊整理：設定與常數 → 工具函式 → DOM 與狀態 → 存檔 → 初始化與登入 → Modal → 資料計算 → 果實轉移 → 渲染 → 事件綁定。

- **新增資料欄位**：把欄位名稱加進 `DATA_FIELDS` 與 `createDefaultState()`，本地存檔、雲端同步、備份匯出入、重置、切換存檔都會自動處理。
- **資料有變動**：呼叫 `commit()`（= 存檔 + 重新渲染 + 記錄復原步驟）。復原紀錄是在 `commit()` 時比對整份資料（`pickData()` 的 JSON）有沒有變，所以只要改資料後呼叫 `commit()` 就能復原，不需要另外處理；程式自動補的資料用 `commit({ history: false })`，不算一步。換成另一份資料時（`applyData()`、`clearMemoryData()`）會清空復原紀錄。
- **可調整的設定**（位於檔案開頭）：`BANK_SLOTS`（鳥籠數）、`FRUITS_PER_CHAR`（每角色果實數）、`PRESETS`（快速組合）、`ATTACK_CATEGORIES`（總覽左側分類）。
- **雲端資料路徑**：`artifacts/{appId}/users/{uid}/fruit_data/{文件}`，預設存檔的文件為 `fruit_assign`，其他存檔為 `fruit_assign_<存檔ID>`，存檔清單為 `fruit_slots`（`{ slots: [{ id, name }] }`）；`appId` 未提供時為 `default-app-id`。
- **LocalStorage**：預設存檔直接使用欄位名稱當 key，其他存檔為 `<存檔ID>_<欄位名稱>`；這台電腦（離線）的存檔清單與名稱為 `global_slot_list`、`slot_names_cache`，登入時不會被雲端清單覆蓋。
- **sessionStorage 快取**：雲端資料依「帳號 + 存檔」分開快取（`fruit_data_cache_<uid>_<存檔ID>`），雲端存檔清單快取為 `fruit_slot_list_cache_<uid>`，登出時會清除；雲端載入期間不會寫入雲端，以雲端資料為準。
- **雲端版本檢查**：雲端文件都有 `version`（每次寫入 + 1）與 `lastUpdated`。寫入都在 `runTransaction` 中先比對兩者是否和上次讀到 / 寫入的相同（`slotDocBase`、`slotListBase`），不同就代表其他裝置改過：存檔資料走 `handleSaveConflict()`（下載備份 + 重新載入），存檔清單走 `mergeSlotLists()`（三方合併）。新增寫入雲端的地方請沿用 `writeToCloud()` / `writeSlotListToCloud()`，不要直接 `setDoc`。
- **從抽卡統計匯入**：讀取抽卡統計的雲端文件 `artifacts/{appId}/users/{uid}/data/gacha_records`（`records` 陣列）或 localStorage `gachaRecords`，使用欄位 `id`、`account`、`date`、`event`、`notes`（「虹夏*3、麒麟兒」格式）、`tag`（`orb` 略過）；設定在檔案開頭的 `GACHA_*` 常數。**抽卡統計改了這些路徑或欄位時，這邊要一起改。** 統一名字時會改寫抽卡統計雲端紀錄的 `notes`（`renameInGachaCloud()`：transaction 讀最新資料、只替換該角色名稱、`version` + 1、`merge: true`），抽卡統計存檔時的三方合併會接收這個修改。 匯入狀態存在存檔欄位 `gachaImports`（`[{ rid, name, linked: [{ n, t }], trashed }]`）與 `gachaAccount`。
- **懸浮工具箱**：工具連結在啟動時從工具箱的 `tools.js`（`window.MS_TOOLS`，網址為 `TOOLBOX_TOOLS_URL`）載入，`THIS_TOOL_ID`（`fruit`）標示目前頁面；讀不到時保留 `index.html` 裡寫死的連結（`.toolbox-home` 的首頁連結一律保留）。新增工具只要改工具箱的 `tools.js`。
- **存檔清單的來源**：`slotList` 登入時是雲端清單，未登入時是本機清單；新增、刪除、改名都透過 `persistSlotList()` 寫回對應的地方。
