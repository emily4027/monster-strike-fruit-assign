## 1.10.4（2026-11-28）改用工具箱共用檔

### 為什麼改

Firebase 設定、懸浮選單、等待載入和資料路徑在五個工具各寫一份，改設定要改五處。現在統一用工具箱的 `shared/firebase.js` 與 `shared/shared.js`。

### 開發與驗證

- `node --test tests` 全部通過；`tests/shared-paths.test.js` 需要同層的 `monster-strike-toolbox` 資料夾。
- 用瀏覽器開本機頁面，確認主控台沒有錯誤、window 全域與選單樣式和改前相同。沒有真的登入，雲端讀寫未實測。

## 1.10.3（未發布）名稱修正改用共用程式

### 為什麼改

抽卡統計的角色名稱修正（例如「砲姐-2(擊種)」改成正確名稱）原本在這裡和角色圖鑑各寫一份，容易不一致。現在統一用角色圖鑑資料庫的 `pools.js`。

### 使用時會發生什麼

- 頁面在載入 `script.js` 前先載入 `/monster-strike-gacha-data/pools.js`。名稱修正的結果和改前相同，包含沒有修正時名稱內空白會被拿掉（`Two for all` 變 `Twoforall`）。
- `pools.js` 載入失敗時，頁面照常使用，只是不套用名稱修正，主控台會有警告。
- 果實分配自己的註記（同族／戰型／擊種／雙削）處理和 `baseNameOf` 維持原樣，因為舊寫法對名稱前後空白的處理和 `pools.js` 不同，換掉會改變比對結果。

### 開發與驗證

- 跑 `node --test tests/`，全部通過。新測試用舊實作算出期望值，對照包裝後的結果。
- 還沒在瀏覽器實際登入匯入一次驗證。

## 1.10.2（未發布）隔離本機存檔

### 為什麼改

同一個 GitHub Pages 網域下的工具共用瀏覽器的本機儲存空間。果實分配現在用 `ms.fruit.` 標示自己的存檔與設定，避免同名資料互相蓋掉。

### 使用時會發生什麼

- 更新後開啟頁面，瀏覽器會先複製舊存檔、存檔名稱、上次選用的存檔及顯示日期設定。原資料留在原處，已有的新資料也會保留。
- 瀏覽器若拒絕存取或空間不足，頁面會繼續開啟，主控台會留下警告，下次開頁會重試。這段期間可能只顯示已搬好的資料。
- 抽卡統計匯入仍讀共用的 `gachaRecords`。登入和雲端暫存沿用現有的 `sessionStorage` 鍵。

### 開發與驗證

- `storage.js` 提供接受短名的 `store`，並依舊存檔清單和已知的編號、時間戳記格式找出多份存檔。歷史設定 `total_slots` 也會複製，現行程式已不讀取這筆設定。
- `node --test tests/` 以假本機儲存驗證搬移、重試、保留既有資料、存檔辨識與共用鍵。瀏覽器及 Firebase 登入未實測。

## 1.9.2（2026-11-27）防止首次上傳互蓋、錯誤提示

### 起因
代碼盤點發現：第一次登入時把本機存檔上傳雲端，是「先看雲端有沒有，沒有再寫」分兩步做。兩台裝置同時第一次登入，可能都以為雲端沒有，後寫的就蓋掉先寫的。其他存檔寫入早就用 transaction，只有這兩處例外。

### 改了什麼
- **首次上傳**：改在 transaction 裡檢查並寫入，雲端已有就不寫。
- **「發現本機存檔」上傳**：原本直接覆寫雲端；現在雲端已有同一份存檔時保留雲端版本，只把它加回存檔清單，並提示可先「下載備份」保存本機版本。
- **本機儲存失敗**（隱私模式、空間已滿）：讀不到當作沒資料，寫不進去跳一次提示，不再讓操作停在一半。
- **未預期的錯誤**：第一次跳提示視窗，之後只寫在主控台，避免連續彈窗。
- 開頁時先連線 Firebase 伺服器。

### 怎麼驗證的
- 本機實際新增角色，確認存進本機；模擬本機空間已滿時跳出「本機儲存失敗」提示；模擬未預期錯誤時跳出提示。

### 沒驗證的部分
- transaction 上傳需要登入雲端，本機沒有實測；寫法和既有的存檔寫入（`writeToCloud`）相同。上線後第一次登入新裝置時留意存檔是否正常出現。
